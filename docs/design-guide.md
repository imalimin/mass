# MASS 系统设计指引

## 1. 系统定位

MASS（Multi-use Agent Systems）是一个支持多用户协作的通用 Agent 创建、管理、调试和运行平台。

用户定义 Agent 的职责与行为，为其组合可复用的 Skills，在平台内调试、发布和使用。平台帮助用户管理版本、持续对话、观察执行过程，并在不同空间之间隔离资源。

“通用”意味着能够面向不同任务组合能力，不意味着每个 Agent 都具备无限能力；实际能完成的任务取决于平台提供且用户获准使用的能力。

## 2. 用户及场景

| 用户 | 典型场景 |
| --- | --- |
| Agent 创建者 | 定义任务助手，组合 Skills，反复调试，发布可用版本 |
| Skill 维护者 | 把常用方法与资源整理为 Skill，发布新版本，供 Agent 复用 |
| Agent 使用者 | 提交任务、连续对话、查看执行进度、获取结果及文件产物 |
| 空间管理者 | 管理成员、使用权限和可用资源，观察空间内的使用情况 |

主要流程：创建或选择 Skill → 定义 Agent → 指定 Skill 版本 → 调试 → 发布 → 执行任务 → 查看过程与结果 → 持续改进。

## 3. 核心目标

1. 降低 Agent 的创建与维护成本，让不同任务能够复用已有 Skills。
2. 让每个发布版本具有明确边界，升级不悄悄改变已有版本。
3. 提供可检查的调试过程，使用户理解 Agent 为什么得到当前结果。
4. 支持持续对话，合理管理历史内容与模型可接收的信息量。
5. 支持多个用户在各自授权空间内协作，避免资源越权访问。
6. 先完成创建、调试、发布、运行和观察的完整闭环，再扩展高级功能。

## 4. 功能要求

### P01 用户与空间

首版提供简单的账号密码登录与退出。用户能够创建或加入空间，在权限范围内查看、编辑和使用资源。空间之间的 Agent、Skills、会话、运行记录、文件和凭证应相互隔离。

首版页面提供空间创建、列表与切换，以及管理者添加已有用户、查看和移除成员的基本操作。用户只能使用被授权的能力和资源；使用中失去权限应明确报错并结束受影响任务，不自动等待重新授权或续跑。首版不要求复杂的角色配置、自助注册、第三方登录或密码找回。

### P02 Agent 管理

用户能够创建、编辑、复制和归档 Agent，描述其职责、行为和工作方式，选择可使用的 Skills 与工具，并维护版本。

用户可以查看历史发布版本与变更差异，选择默认使用的版本。归档不应破坏已被引用的历史记录。

### P03 Skill 管理

用户能够创建、编辑、发布和升级 Skill，维护其中的方法、模板和资源，查看哪些 Agent 正在引用它。

一个 Agent 可以组合多个 Skills，并分别指定它们的版本；运行时使用这些准确版本。Skill 发布新版不会自动改变已有 Agent 版本。

### P04 发布与升级

Agent 和 Skill 均支持可修改的草稿与不可修改的发布版本。修改已发布内容必须产生新版本。

发布后的 Agent 默认在本服务中运行，不需要用户部署到外部服务。用户可以继续使用历史版本，或显式升级到新版本。

### P05 调试

用户可以按当前配置的 Agent 和 Skills 试运行，查看实际使用的定义、版本、上下文及执行结果。

调试开始后，后续编辑不应改变正在进行的调试。调试能够取消，失败时应说明失败位置和原因。

### P06 会话与任务执行

用户可以开始会话、提交任务、持续对话，查看进度和结果，获取文件产物，必要时取消任务。

每个会话拥有持续可用的工作目录，可在连续多次任务中读取和修改文件。每次任务结束保存工作目录快照；再次使用时能够恢复，也可在新会话中显式选择已有快照作为起点。快照恢复文件，不自动继承另一个会话的对话或继续执行中断动作。

同一会话应使用一致的 Agent 定义。平台需要明确展示排队、执行、完成、失败和取消等状态，不能把未完成任务展示为成功。

### P07 上下文管理

系统应管理 Agent 定义、Skill 内容、用户输入、会话历史和工具结果等上下文，让多轮任务能够持续进行。

接近模型可接收内容的限制时，系统应合理压缩历史或处理过大的结果。用户能够查看哪些内容实际提供给模型、哪些内容被压缩或省略，以及相应原因。

历史压缩不应覆盖原始记录；无法容纳关键内容时应明确提示，而不是静默丢弃用户请求或必要指令。所有上下文应有统一、可审计的原始依据，用户能够追查某次输入采用了哪些事实及处理结果。

### P08 工具能力

首版只允许使用平台提供的内置工具。Agent 和 Skill 不能仅凭自身的文字内容获得未授权能力。

内置能力应覆盖文件发现、读取、编辑与整理，方法资源和用户材料的读取，代码计算与数据转换、代码中的网络请求，任务计划维护及文件产物交付。Agent 能完成从读取材料、处理数据到交付结果的任务链；每个 Agent 可按需启用其中的能力。

代码能够读写当前会话的真实工作文件，并在授权能力范围内发起网络请求；不能访问其他会话目录或服务自身文件。文件和网络动作一旦发生，不因代码后续失败自动撤销。

文件修改应避免意外覆盖，删除工作文件不应破坏仍需保留的历史；已交付产物保持当时的内容。用户能够知道工具实际执行了什么、接收了什么参数、返回了什么结果，以及失败或取消造成的影响。计划进度不等同于任务已经成功完成。

### P09 完整运行观察

平台应记录应用实际发送与收到的完整大模型交互，包括输入、输出、工具请求、工具执行结果、失败尝试、上下文处理和最终结果。

用户能够查看完整执行过程，并了解工具结果如何影响下一次模型交互。未被模型返回的信息不属于可记录范围；被截断、脱敏、缺失或因中断未完成的内容必须明确标识。

运行观察还应展示耗时与用量，并在模型服务提供数据时展示实际缓存复用情况；不可获取的数据明确标为未知，不承诺每次请求命中缓存。优化重复输入的成本和延迟时，应优先保证上下文正确、权限有效。认证凭证不得作为可见交互内容泄露。

### P10 资源与运行管理

平台应具备执行时长、并发和用量限制，避免任务无界运行。取消不能被误解为撤销已完成的操作；状态不确定时应明确说明。

用户应能查看历史结果和产物；归档不破坏历史引用。首版不设置业务内容过期策略，版本、会话记录、快照和产物持续保留；删除当前工作文件不删除已经保存的历史内容。

## 5. MVP 范围与非目标

MVP 覆盖 P01—P10，并以本服务内的创建、调试、发布与运行闭环为交付范围。首版不提供独立隔离执行环境，具体执行能力与资源访问边界由下游方案明确，同时必须满足空间隔离目标。

首版不提供独立的自定义外部请求工具、浏览器操作、联网搜索、任意系统程序执行、外部工具接入、外部 Agent 部署、公开共享市场、知识库、跨会话长期记忆、定时任务、多 Agent 协作、高级断点恢复或自动评测平台。

这些能力可以成为后续候选，但不构成当前交付承诺。工程质量测试仍属于首版交付要求，不等同于自动评测平台这一产品功能。

## 6. 成功标准

- 用户可以完成 Skill 和 Agent 从创建、调试到发布、调用的完整流程。
- 多个 Skill 的版本绑定准确，升级不会改变历史 Agent 版本。
- 多轮会话能够处理上下文容量限制，并提供可理解的处理记录。
- 用户可以追查每次模型输入输出与工具结果之间的关系。
- 调试和正式运行有明确的状态、结果、取消和失败说明。
- 空间成员不能越权访问其他空间的数据、文件、凭证或运行记录。
