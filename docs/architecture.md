# MASS 系统架构设计

> 文档约束
> - 本文回答：系统由哪些层级与模块组成，各模块承担什么职责、怎样协作。
> - 包含：逻辑分层、详细功能模块、概念关系、职责边界、跨模块流程、约束及失败语义。
> - 不包含：编程语言与框架选择、第三方库、具体存储产品、表字段、协议路由、实现算法、代码和开发排期。
> - 依据：[系统设计指引](design-guide.md)；所有实现细节归入[技术方案](technical-design.md)，编码与验收顺序归入[工程开发文档](engineering.md)。不新增专题主文档。
> - 状态：架构设计建议，尚未实现；更新：2026-10-17。

## 1. 总体架构

采用模块化单体组织首版：管理功能与任务执行属于同一个服务，通过明确的模块边界协作。前端负责用户交互，后端拥有权限、版本、执行和数据的最终决定权。

```text
用户
 └─ 管理与调试工作台
       └─ 服务接入层
            ├─ 应用管理：身份与空间、Agent/Skill、会话与运行
            └─ 执行核心：调度、上下文、模型交互、内置工具
                   └─ 数据与资源能力：版本内容、运行记录、文件、凭证
```

管理链路负责准备可执行定义，运行链路只消费固定版本或固定调试快照。二者通过版本与运行记录衔接，避免执行时读取正在变化的草稿。

## 2. 逻辑分层

| 层级 | 职责 | 边界 |
| --- | --- | --- |
| 展示层 | 编辑、版本选择、会话、调试和观察 | 不拥有最终权限判断，不直接访问底层存储 |
| 服务接入层 | 身份识别、请求检查、结果返回与事件订阅 | 不执行 Agent 的业务循环 |
| 应用层 | 编排发布、调试、提交、取消与资源查询 | 不依赖某个模型供应商的协议细节 |
| 领域与执行核心 | 版本规则、运行状态、上下文策略、模型与工具循环 | 不依赖页面或具体存储实现 |
| 资源适配层 | 数据存取、模型连接、工具实现、文件与凭证能力 | 实现上层约定，不能绕过领域和权限规则 |

依赖朝向核心约定：外层调用应用能力，核心依赖抽象资源能力，具体适配提供实现。模块可以同进程运行，但不得通过共享可变状态绕过接口和授权。

## 3. 核心概念与关系

| 概念 | 归属与关系 | 必须维持的规则 |
| --- | --- | --- |
| 用户与空间 | 用户通过成员关系加入空间 | 所有业务资源在授权空间范围内访问 |
| Agent | 拥有草稿、发布版本和默认版本 | 草稿变化不影响发布版本 |
| Skill | 拥有方法、资源及发布版本 | 引用绑定到准确版本 |
| 发布版本 | 固定定义及资源集合 | 内容不可原地修改 |
| 调试快照 | 固定本次调试的定义与依赖 | 后续编辑不影响当前调试 |
| 会话 | 固定 Agent 版本或调试快照，包含多次运行 | 不在同一会话中静默切换定义 |
| 运行 | 一次用户请求触发的完整执行 | 拥有固定配置、状态和完整记录 |
| 模型与工具交互 | 一次运行内可出现多次 | 输入、输出和因果关系可追查 |
| 上下文摘要 | 从某段原始历史产生 | 记录来源，不能覆盖原始历史 |
| 产物 | 属于空间及生成它的运行 | 下载与访问同样受到授权控制 |

Skill 提供任务方法，工具提供执行动作。Agent 指令与 Skill 内容不能改变后端的权限判定。

## 4. 功能模块设计

模块编号贯穿技术方案和工程开发文档，便于 AI 将需求、实现与验证对应起来。

### M01 身份与空间

- 输入：登录信息、成员操作、资源访问请求。
- 子能力：身份认证、登录状态、空间管理、成员管理、能力授权。
- 输出：已认证主体、有效空间、允许或拒绝的操作范围。
- 规则：查看、编辑、发布、运行和凭证管理分别授权；后台执行与文件下载同样受约束。长期连接不得永远保留已经撤销的权限。
- 依赖：成员数据和管理审计；其他模块消费其授权能力。

### M02 Agent、Skill 与版本

- 输入：定义、资源、草稿变更、依赖版本和发布请求。
- 子能力：草稿编辑、复制、内容校验、发布、版本对比、默认版本、归档、引用查询。
- 输出：不可变发布版本、准确依赖清单和调试快照。
- 规则：Agent 的每个 Skill 都固定到已发布版本；默认版本切换只影响后续新会话。首次发布可成为默认版本，后续明确切换。
- 边界：发布后即在本服务可用，不引入外部部署对象。被引用版本可归档但不能直接移除内容。

### M03 模型配置与凭证

- 输入：平台支持的模型能力、空间配置和授权凭证。
- 子能力：模型选择、能力描述、参数配置、凭证管理和调用授权。
- 输出：运行可用的有效模型配置及受控凭证使用能力。
- 规则：用户可见定义和 Trace 不暴露凭证明文；运行配置固定后，权限或凭证撤销仍需生效。
- 边界：决定可用配置，不负责上下文组装或模型执行循环。

### M04 会话与运行管理

- 输入：会话创建、用户消息、运行请求、取消请求。
- 子能力：会话定义绑定、历史管理、运行快照、提交去重、状态查询、取消。
- 输出：可被调度的运行、历史记录和最终结果。
- 规则：同一会话一次最多一个待执行或执行中的任务；重复提交不会产生重复任务。会话使用指定版本，未指定时在创建时固定默认版本。
- 边界：接受运行不等于已经执行；浏览器断开不会自动取消已提交任务。

### M05 调度与生命周期

- 输入：待执行运行、空间及平台额度、取消和服务生命周期信号。
- 子能力：任务认领、并发准入、执行归属、存活检查、异常终结。
- 输出：一次获准执行的任务或明确的等待/拒绝结果。
- 规则：任务状态需要可恢复读取；执行通知丢失不应导致任务永久遗失。
- 边界：首版由一个服务实例承担执行；中断运行不自动重放已发生的副作用，未开始的任务可以继续调度。

### M06 Agent 执行器

- 输入：固定运行快照、历史边界、模型和工具能力、运行预算。
- 子能力：执行步骤编排、循环终止、错误处理、取消传播、最终结果形成。
- 输出：最终回复、产物、用量和成功/失败/取消状态。
- 规则：每次实际操作都具有前后记录；必要记录失败时不继续产生后续动作。首版按响应顺序执行工具，补齐一组工具结果后再继续模型交互。
- 边界：不负责工具自身实现、不直接解释供应商专属协议、不参与草稿编辑。

### M07 上下文管理

| 子能力 | 责任 |
| --- | --- |
| 来源加载 | 获取平台规则、固定 Agent 与 Skill 内容、历史、当前请求及工具结果 |
| 上下文组装 | 形成有确定顺序和来源标记的模型输入 |
| 容量预算 | 判断当前输入和预留输出能否被目标模型接收 |
| 历史压缩 | 生成带来源范围的摘要并保留原文 |
| 大结果处理 | 保存完整结果，将可接受的节选或摘要用于后续请求 |
| 上下文检查 | 解释实际发送内容、压缩、截断和未加载内容 |

输入为运行快照与当前历史，输出为本次模型上下文及构建报告。关键指令与当前用户请求不能静默丢弃；工具请求与结果保持配对。

摘要通过统一模型交互能力产生并进入当前运行记录，不另设不可见调用路径。首版仅支持会话内历史与摘要。

### M08 模型交互网关

- 输入：组装后的上下文、有效模型配置和工具描述。
- 子能力：能力校验、请求准备、实际请求发送、流式接收、协议适配、用量归一及有界重试。
- 输出：回复、工具请求、供应商协议状态、原始交互数据和使用量。
- 规则：统一对象与供应商实际载荷都能追踪，不丢失继续会话所需的专有信息。每次重试单独记录，不能把两次尝试拼成一次成功回复。
- 边界：不选择 Skill、不授权工具、不直接调整用户任务。

### M09 内置工具

- 输入：已授权调用、参数、运行工作区和可读取资源。
- 子能力：工具注册、能力说明、参数校验、访问控制、执行、结果归档。
- 输出：带调用标识的结果、错误和副作用状态。
- 规则：工具授权同时满足空间政策与 Agent 配置；Skill 资源只读，运行文件与历史发布内容隔离。
- 边界：首版仅开放平台实现的工具，不开放任意代码、脚本或外部工具插件；文字指令不授予额外权限。

### M10 Trace、用量与审计

- 输入：上下文处理、每次模型交互、每次工具执行、状态变化和管理操作。
- 子能力：完整交互记录、时间线、调用因果关系、用量汇总、查询、管理审计。
- 输出：可回看和订阅的事件、完整载荷、用量与审计结果。
- 规则：这是业务数据，不能仅以普通日志代替。未完成、脱敏、截断或过期都要显式标记。
- 边界：历史回看不重新执行工具；管理审计与模型对话分开呈现。

### M11 文件、资源与产物

- 输入：版本资源、用户附件、工具文件和大交互载荷。
- 子能力：受控存储、完整性校验、运行工作区、产物保存、权限下载、保留与清理。
- 输出：稳定资源引用和授权访问能力。
- 规则：版本资源不可变；工作区可清理，但已归档产物及仍被引用的内容不能随之消失。不能仅保存会失效的临时下载地址。
- 边界：文件隔离是应用层保障，不能宣称为独立操作系统执行隔离。

### M12 管理与调试工作台

| 页面模块 | 功能 |
| --- | --- |
| 登录与空间 | 登录、空间切换、成员及资源权限 |
| Agent 与 Skill 编辑 | 定义编辑、资源管理、版本选择、发布及归档 |
| 版本详情 | 内容差异、依赖清单、默认版本切换 |
| 会话与调试 | 输入任务、显示状态、流式结果、取消和重试入口 |
| 运行观察 | 步骤时间线、完整模型输入输出、工具结果、上下文检查 |
| 产物与设置 | 文件获取、模型配置、凭证管理、使用量 |

页面之间共享统一空间上下文。切换空间时不得混入旧空间的缓存或流式事件；界面权限只用于体验，最终授权属于后端。

### M13 服务基础能力

- 输入：服务配置、启动/停止请求及资源健康信息。
- 子能力：模块组装、服务接入、错误规范、配置校验、生命周期、健康状态和运维观测。
- 输出：可启动、可停止、可诊断的服务运行环境。
- 边界：运维观测用于服务健康，业务 Trace 用于任务解释，二者不能互相替代。

## 5. 跨模块协作

### 5.1 创建与发布

工作台 → 身份与空间鉴权 → 定义管理检查草稿和依赖 → 资源模块固定内容 → 版本管理发布 → 管理审计。

发布要么完整可读，要么失败；不能出现已发布版本引用缺失资源或不确定 Skill 版本的状态。

### 5.2 调试与正式运行

工作台或调用方 → 会话与运行管理 → 定义解析与模型授权 → 固定快照 → 调度 → 执行器。

调试使用草稿快照，正式运行使用发布版本。两种模式共享同一执行器、上下文、工具和 Trace，避免调试与正式运行产生两套语义。

### 5.3 模型与工具循环

执行器 → 上下文构建 → 记录请求 → 模型网关 → 记录响应 → 工具校验与执行 → 记录结果 → 下一次上下文。

无工具请求且回复完整时结束；超出预算、不可恢复错误或取消时按原因终结。上下文摘要也走模型网关和 Trace，不绕过记录。

### 5.4 观察与文件获取

工作台经授权查询运行状态和记录，通过持续事件展示进展；需要原始载荷或文件时由资源模块受控读取。运行完成、订阅断开和文件清理属于不同生命周期。

## 6. 状态、数据归属与一致性

运行经历待执行、执行中，以及成功、失败、已取消三种终态。超时是失败原因。取消请求和实际停止执行是不同事件，不能过早释放仍在执行的工作。

运行配置和版本固定，权限可被撤销；实际操作同时遵循固定定义与当前授权。默认版本变化不影响旧会话，Skill 新版不影响旧 Agent。

原始消息、完整交互和上下文摘要分别保存。失败运行中的不完整工具链不直接作为正常历史继续使用；已确认副作用和结果未知状态应向后续交互说明。

跨空间关系不允许通过直接资源标识绕过授权。版本资源、运行状态、记录和产物各有归属与保留规则，具体字段与持久化方案由技术方案定义。

## 7. 失败边界与演进

网络发送与结果保存之间可能发生中断，系统应诚实呈现未完成或结果未知，不保证外部动作恰好执行一次。恢复旧记录不等于重做旧动作。

首版不在任意步骤自动恢复，也不提供任意用户代码隔离。后续可以增加独立执行资源、更多模型适配和工具能力，但要保持版本解析、授权、上下文和记录的统一入口。

未来功能需要先在设计指引确认范围，再更新本文件的模块关系，技术方案中的实现，以及工程开发文档中的建设和验收步骤。
