# MASS 系统架构设计

> 文档约束
> - 本文回答：系统由哪些层级与模块组成，各模块承担什么职责、怎样协作。

## 1. 总体架构

简化图示：[系统分层架构图（含技术标注）](images/system-layered-architecture.png)。

采用模块化单体组织首版：工作台页面、应用接口、管理功能与任务执行由同一个应用服务提供，共用配置入口和访问入口，通过明确的模块边界协作。前端负责用户交互，后端拥有权限、版本、执行和数据的最终决定权。数据存储、对象存储和模型端点是该服务依赖的外部资源，不另拆应用服务。

```text
用户
 └─ 管理与调试工作台
       └─ 服务接入层
            ├─ 应用管理：身份与空间、Agent/Skill、会话与运行
            └─ 执行核心：调度、上下文、模型交互、内置工具
                   └─ 数据与资源能力：版本内容、运行记录、文件、凭证
```

管理链路负责准备可执行定义，运行链路只消费固定版本或固定调试快照。会话与执行事实进入统一会话日志，上下文只从固定日志边界和不可变内容引用投影，运行状态、聊天历史与 Trace 是面向不同用途的视图。版本管理、身份和空间管理保持各自的业务职责。

## 2. 逻辑分层

| 层级 | 职责 | 边界 |
| --- | --- | --- |
| 展示层 | 编辑、版本选择、会话、调试和观察 | 不拥有最终权限判断，不直接访问底层存储 |
| 服务接入层 | 身份识别、请求检查、结果返回与事件订阅 | 不执行 Agent 的业务循环 |
| 应用层 | 编排发布、调试、提交、取消与资源查询 | 不依赖某个模型供应商的协议细节 |
| 领域与执行核心 | 版本规则、运行状态、上下文策略、模型与工具循环 | 不依赖页面或具体存储实现 |
| 资源适配层 | 数据存取、模型连接、工具实现、文件与凭证能力 | 实现上层约定，不能绕过领域和权限规则 |

依赖朝向核心约定：外层调用应用能力，核心依赖抽象资源能力，具体适配提供实现。首版模块在同一服务进程运行，但不得通过共享可变状态绕过接口和授权。

## 3. 核心概念与关系

| 概念 | 归属与关系 | 必须维持的规则 |
| --- | --- | --- |
| 用户与空间 | 用户通过成员关系加入空间 | 所有业务资源在授权空间范围内访问 |
| Agent | 拥有草稿、发布版本和默认版本 | 草稿变化不影响发布版本 |
| Skill | 拥有方法、资源及发布版本 | 引用绑定到准确版本 |
| 发布版本 | 固定定义及资源集合 | 内容不可原地修改 |
| 调试快照 | 固定本次调试的定义与依赖 | 后续编辑不影响当前调试 |
| 会话 | 固定 Agent 版本或调试快照，包含多次运行 | 不在同一会话中静默切换定义 |
| 运行 | 一次用户请求触发的完整执行 | 拥有固定配置、状态和完整记录 |
| 模型与工具交互 | 一次运行内可出现多次 | 输入、输出和因果关系可追查 |
| 会话日志 | 按顺序记录定义、输入、模型交互和工具结果 | 原始事实追加保存，引用内容不可变 |
| 上下文投影 | 从固定日志位置与固定规则生成 | 保存来源与生成结果，可追溯至实际模型请求 |
| 上下文摘要 | 从明确的完整交互单元产生 | 记录准确来源，保存后复用，不能覆盖原始历史 |
| 压缩阶段 | 一份固定基础内容及后续追加交互 | 阶段内保持已有内容稳定，必要变化开启新阶段 |
| 会话工作目录与快照 | 每个会话独立目录，多次运行连续使用；每次运行结束保存快照 | 快照固定文件内容；恢复不重放动作，不自动继承另一会话历史 |
| 产物 | 属于空间及生成它的运行 | 下载与访问同样受到授权控制 |

Skill 提供任务方法，工具提供执行动作。Agent 指令与 Skill 内容不能改变后端的权限判定。

## 4. 功能模块设计

模块编号贯穿技术方案和工程开发文档，便于 AI 将需求、实现与验证对应起来。

### M01 身份与空间

- 输入：登录信息、成员操作、资源访问请求。
- 子能力：账号密码验证、登录状态、空间管理、成员归属、基础管理权限。
- 输出：已认证主体、有效空间、允许或拒绝的操作范围。
- 规则：首版按空间成员与空间管理者区分基础权限，不建立细粒度角色体系；后台执行与文件下载同样受约束。长期连接不得永远保留已经撤销的权限。
- 依赖：成员数据和管理审计；其他模块消费其授权能力。首版工作台提供登录、空间创建/切换和成员查看/添加/移除；账号初始化由服务管理入口承担，高级账号体系后续扩展。权限撤销返回明确错误并停止该主体受影响的任务，不增加暂停授权或恢复执行状态。

### M02 Agent、Skill 与版本

- 输入：定义、资源、草稿变更、依赖版本和发布请求。
- 子能力：草稿编辑、复制、内容校验、发布、版本对比、默认版本、归档、引用查询。
- 输出：不可变发布版本、准确依赖清单和调试快照。
- 规则：Agent 的每个 Skill 都固定到已发布版本；默认版本切换只影响后续新会话。首次发布可成为默认版本，后续明确切换。
- 边界：发布后即在本服务可用，不引入外部部署对象。被引用版本可归档但不能直接移除内容。

### M03 模型配置与凭证

- 输入：平台支持的模型能力、空间配置和授权凭证。
- 子能力：模型选择、能力描述、参数配置、凭证管理和调用授权。
- 输出：运行可用的有效模型配置及受控凭证使用能力。
- 规则：用户可见定义和 Trace 不暴露凭证明文；运行配置固定后，权限或凭证撤销仍需生效。
- 边界：决定可用配置，不负责上下文组装或模型执行循环。

### M04 会话与运行管理

- 输入：会话创建、用户消息、运行请求、取消请求。
- 子能力：会话定义绑定、原始输入登记、运行快照、提交去重、状态查询、取消；通过统一日志提交事实并维护消息和运行视图。
- 输出：可被调度的运行、历史记录和最终结果。
- 规则：同一会话一次最多一个待执行或执行中的任务；重复提交不会产生重复任务。会话使用指定版本，未指定时在创建时固定默认版本。
- 边界：接受运行不等于已经执行；浏览器断开不会自动取消已提交任务。消息展示和最终回复通过引用原始事实形成，不能另建可独立修改的上下文来源。

### M05 调度与生命周期

- 输入：待执行运行、空间及平台额度、取消和服务生命周期信号。
- 子能力：调度负责并发准入、任务认领与交接；运行监督负责执行归属、取消传播、存活检查、终态提交及中断恢复。
- 输出：一次获准执行的任务或明确的等待/拒绝结果。
- 规则：任务状态需要可恢复读取；执行通知丢失不应导致任务永久遗失。
- 边界：首版由一个服务实例承担执行；中断运行不自动重放已发生的副作用，未开始的任务可以继续调度。

### M06 Agent 执行器

- 输入：固定运行快照、历史边界、模型和工具能力、运行预算。
- 子能力：执行步骤编排、循环终止、错误处理、取消传播、最终结果形成。
- 输出：已记录的最终响应引用或停止原因，交给运行监督统一提交终态；产物和用量来自实际交互记录。
- 规则：每次实际操作都具有前后记录；必要记录失败时不继续产生后续动作。首版按响应顺序执行工具，补齐一组工具结果后再继续模型交互。
- 边界：执行器只编排步骤，不直接提交运行终态；上下文、模型、工具及运行限额各自独立。运行限额控制覆盖任务调用、摘要和重试，与调度并发配额分开；不负责工具自身实现、供应商专属协议或草稿编辑。

### M07 上下文管理

| 子能力 | 责任 |
| --- | --- |
| 原始事实读取 | 读取统一会话日志的固定位置及其不可变内容引用 |
| 确定性投影 | 在相同事实、配置、摘要和规则下生成相同模型可见内容 |
| 容量规划 | 计算工具、关键指令、历史和输出预留，决定是否需要压缩 |
| 历史摘要 | 形成带准确来源的新增记录，后续复用保存的结果 |
| 稳定追加 | 固定指令、工具和阶段基础内容，后续完整交互按顺序追加 |
| 大结果处理 | 保存完整结果，固定本次使用的节选或摘要 |
| 上下文检查 | 串联原始事实、选取/省略规则、投影结果与实际请求 |

容量规划与确定性投影分开：规划可以触发有记录的摘要调用，投影本身只转换已有事实，不在重建时重新生成摘要。工具请求与结果成组处理；不完整交互和未知副作用有明确说明，不能静默当作成功历史。

历史压缩按阶段发生，每个阶段的摘要和基础内容固定，正常多轮只追加新交互。必要配置变化、压缩或协议变化可以改变前缀，并说明原因；权限和正确性优先于缓存。Agent/Skill 版本变化仍按会话版本规则处理。

系统保证输入可追溯和自身投影的稳定性，模型端实际缓存命中由外部服务决定。投影结果缓存与模型推理缓存分别观察；未提供命中数据时显示未知，不承诺每次命中。首版仅支持会话内历史与摘要。

### M08 模型交互网关

- 输入：组装后的上下文、有效模型配置和工具描述。
- 子能力：能力校验、请求准备、实际请求发送、流式接收、协议适配、用量归一及有界重试。
- 输出：回复、工具请求、供应商协议状态、原始交互数据和使用量；交互事实写回统一日志，并关联产生请求的投影。
- 规则：模型框架的语义交互与实际传输载荷分别记录，统一对象与供应商实际载荷都能追踪，不丢失继续会话所需的专有信息。每次重试单独记录，不能把两次尝试拼成一次成功回复。
- 边界：不选择 Skill、不授权工具、不直接调整用户任务。模型缓存能力通过适配层表达，不能用远端缓存引用代替平台可审计的上下文来源；缓存失效有明确恢复路径。

### M09 内置工具

- 输入：已授权调用、参数、运行工作区和可读取资源。
- 子能力：注册与版本解析提供准确能力；工具调度负责校验、授权、限额和结果归档；内置工具实现负责具体动作。工具实现不能另行宣告运行完成；本地文件及网络效果与结果记录不是共同事务。
- 输出：带调用标识的结果、错误和副作用状态，追加到统一日志。失败与“没有产生副作用”分别判断；结果未知不能自动重试。
- 规则：工具授权同时满足空间政策与 Agent 配置；Skill 资源只读，运行文件与历史发布内容隔离；文件工具和代码工具通过同一资源模块访问当前会话的真实临时工作目录；工作区、方法资源和会话附件分别鉴权，不按可猜测标识授予权限。
- 能力分组：文件发现/搜索/读取/修改/整理，固定版本方法资源与会话附件读取，受限计算，计划维护，固定版本产物交付。
- 代码计算：每次执行使用独立计算状态，允许通过受控接口读写当前会话工作目录并访问网络；不要求预先列举所有文件，支持连续读取。文件写入及网络效果立即发生，后续异常不回滚，完整记录已确认或未知效果。应用级能力限制不等于系统级隔离。
- 计划与交付：计划变化和产物登记共同进入统一事实来源；计划不另启执行循环，产物固定内容版本。界面展示专用视图，模型使用对应工具结果，不能重复注入事实。
- 边界：允许平台限定能力内的计算，不开放任意系统程序、外部工具插件、独立自定义请求工具、浏览器或联网搜索工具；读取方法资源不等于执行其中的脚本。文字指令不授予额外权限。

### M10 会话日志、Trace、用量与审计

- 输入：定义绑定、用户输入、上下文处理、模型与工具交互、状态变化，以及独立的管理操作。
- 子能力：统一事实追加、顺序与因果关系、不可变内容关联、查询视图维护、计划与产物事实、标准前端交互事件适配、完整交互回看、用量和缓存统计、管理审计。
- 输出：统一会话日志，以及从中形成的运行时间线、消息与状态视图；提供上下文投影唯一的原始事实入口。
- 规则：区分准备、进行中、已完成、失败和结果未知；日志与关键状态视图共同提交。未完成、脱敏、截断或缺失显式标记。原文、结构化内容和派生摘要保留来源关系。
- 边界：运行 Trace 使用统一日志，不独立复制另一套事实；身份、成员、发布和凭证操作采用管理审计。前端事件是内部事实的派生表达，可一对多映射，并维护自己的恢复位置；上下文仍基于原始日志。视图重建不触发模型或工具；应用层追加规则不能被描述为绝对防篡改能力。

### M11 文件、资源与产物

- 输入：版本资源、用户附件、工具文件、大交互载荷和会话快照。
- 子能力：会话临时工作目录、文件操作、运行结束快照、恢复、不可变内容保存、产物交付和权限下载。
- 输出：当前会话的文件访问能力，以及持久资源与快照引用。临时目录跨同会话的运行复用，持久快照存入远端资源存储。
- 规则：先停止文件写入再保存完整目录快照；快照确认保存后才能报告任务成功。失败或取消也保存已经发生的文件变更；保存失败明确报错，不能把临时目录当作持久保存成功。重启只恢复已确认的快照，中断期间未保存的修改可能丢失。
- 历史：版本、日志、快照与产物不设置过期或自动删除策略。当前目录修改不改变历史快照；产物发布独立固定内容，不把目录快照当作全部文件已经交付。
- 边界：快照用于文件恢复，模型上下文仍只来自统一日志及不可变内容；文件隔离是应用层保障，不宣称为操作系统沙箱。

### M12 管理与调试工作台

| 页面模块 | 功能 |
| --- | --- |
| 登录与空间 | 密码登录、退出、空间创建/列表/切换；管理者查看、添加已有用户及移除成员 |
| Agent 与 Skill 编辑 | 定义编辑、资源管理、版本选择、发布及归档 |
| 版本详情 | 内容差异、依赖清单、默认版本切换 |
| 会话与调试 | 输入任务、显示状态、流式结果、取消；查看工作目录快照并选择新会话的恢复起点 |
| 运行观察 | 原始事件与因果关系、完整模型交互、工具结果、投影来源、压缩阶段与真实缓存统计 |
| 产物与设置 | 文件获取、模型配置、凭证管理、使用量 |

页面之间共享统一空间上下文。切换空间时不得混入旧空间的缓存或流式事件；界面权限只用于体验，最终授权属于后端。

### M13 服务基础能力

- 输入：服务配置、启动/停止请求及资源健康信息。
- 子能力：模块组装、页面与接口统一接入、错误规范、统一配置校验、生命周期、健康状态和运维观测。
- 输出：可启动、可停止、可诊断的服务运行环境。
- 边界：运维观测用于服务健康，业务 Trace 用于任务解释，二者不能互相替代。

## 5. 跨模块协作

### 5.1 创建与发布

工作台 → 身份与空间鉴权 → 定义管理检查草稿和依赖 → 资源模块固定内容 → 版本管理发布 → 管理审计。

发布要么完整可读，要么失败；不能出现已发布版本引用缺失资源或不确定 Skill 版本的状态。

### 5.2 调试与正式运行

工作台或调用方 → 会话与运行管理 → 定义解析与模型授权 → 固定快照 → 调度 → 执行器。

调试使用草稿快照，正式运行使用发布版本。两种模式共享同一执行器、上下文、工具和 Trace，避免调试与正式运行产生两套语义。

### 5.3 模型与工具循环

执行器 → 固定日志读取边界 → 容量规划与上下文投影 → 保存投影和请求 → 模型交互写回日志 → 工具执行写回日志 → 从新日志边界进行下一次投影。

需要摘要时，先保存其来源和生成交互，再使用已保存摘要投影。实际请求关联逻辑投影，逻辑投影关联原始事实；审计事件不会全部进入模型输入。

无工具请求且回复完整时结束；超出预算、不可恢复错误或取消时按原因终结。上下文摘要也走模型网关和 Trace，不绕过记录。

### 5.4 观察与文件获取

工作台经授权查询运行状态和记录，通过标准交互事件展示进展；协议适配器区分消息内容、工具参数、执行结果与运行终态。工具参数结束不等于执行成功，订阅连接失败不等于任务失败。前端从已应用的事件位置恢复，原始审计位置与展示恢复位置分别维护。需要原始载荷或文件时由资源模块受控读取。运行完成、订阅断开和文件清理属于不同生命周期。

## 6. 状态、数据归属与一致性

运行经历待执行、执行中，以及成功、失败、已取消三种终态。超时是失败原因。取消请求和实际停止执行是不同事件，不能过早释放仍在执行的工作。

运行配置和版本固定，权限可被撤销；实际操作同时遵循固定定义与当前授权。任一阶段发现权限失效，立即拒绝后续业务动作并通知停止正在执行的调用，返回权限错误；已发生效果不回滚。系统仍负责记录错误及保存已有文件快照，收尾不授予被移除用户任何资源读取权限。默认版本变化不影响旧会话，Skill 新版不影响旧 Agent。

原始消息、完整模型交互、工具结果和摘要通过统一日志及不可变引用保存；同一事实可以支撑多个视图。投影绑定固定历史边界，期间新增记录不悄悄改变已生成输入。失败运行中的不完整工具链不直接作为正常历史继续使用；已确认副作用和结果未知状态应向后续交互说明。

跨空间关系不允许通过直接资源标识绕过授权。关系数据与资源对象跨存储写入时，先确认对象存在再建立可见引用，失败留下的未引用对象不能被误认作已发布资源；首版不建设自动回收和过期机制。版本资源、运行状态、记录和产物各有归属，具体字段与持久化方案由技术方案定义。

## 7. 失败边界与演进

网络发送与结果保存之间可能发生中断，系统应诚实呈现未完成或结果未知，不保证外部动作恰好执行一次。恢复旧记录不等于重做旧动作。

首版不在任意步骤自动恢复，也不提供任意用户代码隔离。后续可以增加独立执行资源、更多模型适配和工具能力，但要保持版本解析、授权、上下文和记录的统一入口。

未来功能需要先在设计指引确认范围，再更新本文件的模块关系，技术方案中的实现，以及工程开发文档中的建设和验收步骤。
