# MASS 创意需求与技术方案

「创意」让用户在普通会话里创建或升级 Agent、迭代 Skills，再从会话 Workspace 发布。本方案是 MVP（P01—P10）之后的最小增量。

## 1. 产品需求

空间侧边栏新增「创意」，作为空间默认首页。新建 Agent 走完整三步；升级已有 Agent 从管理页直达第 2 步：

1. **创意首页。** 页面中央展示一个内含发送按钮的圆角输入框。用户输入新建 Agent 的要求并发送，不需要先选 Skills，也不需要到会话页再发一次。
2. **创意会话。** 预设创作 Agent 接收用户消息，对话、运行、Workspace 文件树、文件预览和文件交付均复用普通会话。用户通过对话整理和修改 Workspace 中的 `AGENTS.md` 和 Skills。页面隐藏会话记录入口，顶部提供返回创意首页和「去发布」入口。当前会话排队或运行期间，「去发布」置灰，提示「请等待当前运行结束」。普通 ZIP 产物照常交付，不是发布的前置条件。
3. **发布弹窗。** 点击「去发布」后先检查 Agent 是否绑定模型。没有模型时，提示并让用户选择当前空间的可用模型，选好后再检查发布清单；已有模型则不提供更换入口。发布清单只读，标明新建或升级的 Agent，以及新建、更新或仅引用的 Skills。不在弹窗内展示文件树或文件预览，不允许修改其他 Agent 配置、切换目标，或添加、移除、更换 Skill。查看或调整工程内容时，返回创意会话。确认后先处理 Skills，再处理 Agent；逐项复用目录草稿的创建或更新及发布流程。中途失败时展示已发布、草稿已保存但未发布及未处理的项；关闭弹窗回到原会话。

**已有 Agent 入口。** 在 Agent 管理页点击任意 Agent，直接进入第 2 步，不经过创意首页，也不自动发送消息。页面标明正在迭代哪个 Agent。默认从 TOS 恢复该 Agent 最新已发布版本，以及它所绑定的各个 Skill 的最新已发布版本，作为会话 Workspace 的起点。从未发布的 Agent 才以现有草稿为起点，并在原条目上发首版。现有的手动编辑和普通会话入口仍单独保留。归档 Agent 沿用现有规则，恢复归档后才能发布。

**普通会话的工作目录。** 左侧常驻会话记录，无需手动展开；右侧常驻当前会话的 Workspace 文件树，文件夹可展开和收起。桌面默认从左到右是「会话记录｜对话｜文件树」；点击文件后，在对话和文件树之间显示只读预览。关闭预览后恢复原布局，保留当前聊天和目录展开状态。创意会话隐藏左侧会话记录，复用相同的文件树及预览。

**Agent 权限范围。** 普通创建和创意新建均默认为「空间内」，创建时不提供权限范围选项。创建后，管理者可在所属空间的 Agent 管理页切换「空间内」或「公开」。「空间内」仅所属空间可按现有权限使用；「公开」允许已登录用户在自己有权访问的任意空间中使用该 Agent 的已发布默认版本，不开放匿名访问、草稿或管理权限。内置创作 Agent 设置为「公开」，供各空间的创意入口共用；创作会话、工作区、产物以及最终发布的 Agent 和 Skills 都留在用户当前空间。

新版本不修改旧版本或已有会话所固定的版本。已有 Skill 发新版，不自动升级其他 Agent 的绑定。不做创意会话内的手动文件编辑器、多人并发编辑、独立草稿管理或专用试跑链路。只预留内置创作 Agent 的配置入口，不设计或实现其定义、提示词和工具。创作 Agent 不可用时，只影响创意入口，已有创建、调试和会话方式不变。

## 2. 技术方案

### 2.1 配置与普通会话

在 `mass.yaml` 和示例配置中预留以下配置：

```yaml
creativity:
  agent_id: ""
  agent_workspace_id: ""
```

`creativity.agent_workspace_id` 是内置创作 Agent 所在的空间 ID；`creativity.agent_id` 是该空间内的 Agent ID。创意首页和 Agent 管理页共用这组配置，服务端按这两个值精确查找，不按名称或在其他空间兜底。配置只负责定位，跨空间运行权限由 Agent 的「公开」设置决定。

空间索引 `/spaces/:spaceId` 默认展示「创意」，侧边栏选中同名项；原「空间概览」移到独立路由。任一配置缺失、无法定位或创作 Agent 不可用时，仍可进入创意首页，但输入区提示不可发送，管理页的创意迭代入口提示不可用。普通流程不受影响。

复用 `SessionWorkspace` / `Conversation`，由创意首页和 Agent 管理页的迭代入口隐藏会话记录入口。创意顶栏提供返回空间索引、「去试试」和「去发布」，下方沿用普通会话标题栏。普通会话沿用原有会话路由和记录查询。从创意首页进入时，首条文本和请求键通过路由状态交给会话，不写进 URL；使用现有创建与提交链路自动提交一次。失败保留输入，重试沿用原请求键；接收成功后清除待发状态，重渲染或后退不会再发。

创作 Agent 使用普通会话的消息、Run、文件工具和跨轮 Workspace，不新增会话类型、运行分支、工具或快照机制。Workspace 中的 `AGENTS.md` 是待发布 Agent 的文件，不替换创作 Agent 当前使用的指令。ZIP 等文件仍通过已有的 `publish_artifact` 交付，产物展示和下载不变；目录发布不读取 `artifact_id`，不新增交付接口。

**迭代已有 Agent。** 从管理页进入时，服务端按当前空间权限解析目标 Agent 的最新可用正式版本：按发布时间取最新，排除调试快照和已归档的版本，不以默认版本或版本标签判断。用该版本的绑定确定要恢复的 Skill 及其顺序，再分别解析这些 Skill 的最新可用正式版本。从未发布过的目标 Agent 使用现有草稿确定定义和 Skill 范围；有发布历史但无可用版本，或某个绑定的 Skill 定义已归档、无可用版本时，提示具体项，不创建会话、不静默回退或跳过。会话创建后才归档的 Skill 不影响现有会话继续对话，也不自动改绑；发布时拒绝仍包含该 Skill 的清单。

**持久化初始化来源。** 以会话 `session.jsonl` 的 `session.created` 为权威记录，不只存在路由状态、进程内存或 `proj.json`。记录中新增可选的 `creativity` 对象：普通会话省略，新建 Agent 的创意会话不带迭代目标；迭代时记录 `target_agent_id`、`target_version_id`、`target_draft_revision`，以及按绑定顺序排列的 `skill_bases`（每项为实际恢复的 `skill_id` 和 `version_id`）。从未发布的目标省略 `target_version_id`，用固定的 `target_draft_revision` 读取原草稿；有正式版时该修订号只用于发布冲突校验。后续发布以会话记录里的目标 Agent 为准，不从 URL 或可写文件取目标。

首次 Run 快照提交前，工作区为空或因重启丢失时，Workspace 初始化从创建记录中的固定来源读取 TOS 版本包或草稿修订，恢复 `AGENTS.md`、`agent.json`、各 Skill 的 `SKILL.md` 和资源，并生成 `proj.json`。Agent 的目录配置以 JSON 写入新工作区。初始化完整后才能开始对话，不把空工作区恢复当作初始化成功。读取失败提示重试；原草稿修订已不可读时，提示从管理页重新进入，不重新解析「最新」。一旦有已提交的会话快照，后续按普通 Workspace 恢复，不再用初始化来源覆盖改稿。运行时 `agent_id` 仍是预设创作 Agent；初始化不改目录草稿或历史版本。

**文件大小限制。** 创意迭代同时遵守现有 Skill 资源规范（单文件最多 8 MiB）及普通 Workspace 的快照限额（`storage.max_object_bytes` 默认 2 MiB，且受 `storage.max_workspace_bytes` 总量限制），不为创意会话设置例外。已有 Skill 可以合法发布但不满足创意迭代的恢复条件；超限时不生成不完整的工作区，也不影响该 Skill 在普通会话中的使用。从 Workspace 发布只读取已提交的 Run 快照，不能用宿主文件补齐。

#### Agent 权限范围与跨空间使用

- 权限范围保存在 Agent 定义上，不随版本或草稿变化：`visibility: space | public`。已有 Agent 缺省为 `space`。创意新建 Agent 默认 `space`，发布弹窗不提供范围设置；之后可在所属空间的 Agent 管理页调整。创意升级只发新版，不改变原范围。设置范围复用源空间现有的 Agent 管理权限，不从 Workspace 文件读取。
- 普通会话创建区分**会话空间**和 **Agent 来源空间**。同空间调用沿用原规则；跨空间时，服务端校验用户有权在会话空间创建会话，以及来源 Agent 公开、有可用的已发布默认版本。`session.created` 继续用 `space_id` 表示会话空间，用 `agent_id`、`version_id` 固定选中的 Agent 版本；跨空间时额外记录 `agent_source_space_id`，缺省为会话空间。普通会话组件在跨空间场景使用服务端返回的已发布元数据渲染，不调用来源空间的 `GET /draft`。刷新页面从会话记录解析来源与固定版本，不改绑当前默认版本，不复制 Agent 到当前空间。
- 跨空间 Run 的模型解析和 Skill 资源读取使用服务端从固定版本解析出的依赖：只访问该版本选定的模型，以及绑定的准确 Skill 版本和资源，不接受客户端或工具指定任意来源空间、模型或对象 ID。模型凭证仅供服务端调用；不授予来源空间成员身份，不开放来源目录、草稿、通用对象读取或凭证接口。工作区、会话记录、附件和产物仍按会话空间隔离。设为公开时提示管理者：已绑定的 Skill 内容可能通过 Agent 输出被跨空间使用者看到。
- 每次接受新的跨空间 Run 前，服务端重新校验来源 Agent 仍公开且未归档，固定的正式版本仍可用；切回「空间内」或归档后，拒绝新会话及新 Run，不改写已保存的历史。运行使用已固定版本，来源默认版本切换不会改绑已有会话。Agent 未公开或没有可用默认版本时，外部空间不能通过配置绕过新会话的校验。

### 2.2 通用工作目录浏览

在 `SessionWorkspace` 中实现通用的文件树和只读预览，以当前 `session_id` 为作用域。打开 `.md` 文件时默认渲染 Markdown，可在「查看原文」和「渲染展示」之间切换。打开、切换或关闭文件预览只调整布局，不重新挂载 `Conversation`、断开消息流或清空输入；切换会话时清除上一个会话的选中文件和目录展开状态。

文件树和预览通过会话级只读接口读取当前 Workspace：展开时按目录获取条目，点击后按相对路径读取文件。服务端复用会话访问校验、工作目录锁和文件路径校验，不跟随符号链接或暴露宿主路径。宿主目录确实缺失且会话已有已提交快照时，首次浏览从最近已提交的 Run 快照恢复到宿主；不会覆盖仍存在的目录，即使该目录为空。未提交过快照时，已有 Agent 迭代仍按固定基线初始化，全新会话可以为空。浏览与恢复不触发 Run、写入新快照或交付产物。首版进入页面、会话初始化完成或 Run 结束后刷新已展开的目录，不做运行中实时文件推送。预览仅展示大小限制内的 UTF-8 文本，不执行文件内容；二进制、过大或已删除的文件显示原因。

会话内文件树浏览当前 Workspace；发布弹窗仍只检查固定快照内可发布的 Agent 与 Skills。打开或关闭会话内预览不影响发布清单。

### 2.3 发布预览与文件扫描

「去发布」和弹窗中的「确认发布」复用普通会话的活动 Run 状态，当前会话有 `queued` 或 `running` 的 Run 时禁用。运行结束且最近一轮已提交 Workspace 快照后才允许打开弹窗，不静默回退到旧快照。弹窗预览不占用发布锁。

点击「去发布」时固定该轮的 `workspace_snapshot_id`，在同一会话路由上打开弹窗，保持会话组件挂载。服务端校验当前空间和会话访问权限及快照归属，从既有快照扫描根目录的 `AGENTS.md`、`agent.json`、可选的 `proj.json`，以及 `skills/<name>/` 下的 `SKILL.md` 和资源，不扫描其他目录。所需文件缺失或仅保存在宿主时，提示具体路径，不生成不完整的发布清单。预览和确认读取同一快照；需要发布后续对话中的改动时，重新打开弹窗。

弹窗只能浏览、为未绑定的 Agent 选择模型、确认、关闭或在失败后重试。服务端从快照内读取 `agent.json` 和可选的 `proj.json`，两个文件均使用 JSON 格式。未绑定模型时，只有当前空间中已启用且满足 Agent 能力要求的模型可补齐发布配置，随后才校验 Skills。模型选择不修改工作区和 Run 快照；首次确认时固定在发布计划中，重试沿用。确认请求不能替换已有的模型绑定，也不能覆盖 Agent 目标、其他配置或 Skill 绑定。需要改内容或增删 Skill 时，返回创意会话调整 Workspace 中的文件及 `proj.json`，等待新 Run 提交快照后再打开弹窗；需要更换已有 Agent 的发布目标时，从管理页进入对应 Agent 的创意会话。`catalog` 复用现有访问权限、配置和资源校验，不把 Workspace 中声明的 ID 当作授权。

#### `proj.json` 文件结构

`proj.json` 位于 Workspace 根目录，只声明已有 Skill 的绑定及其基准版本，不存 Agent 配置、发布目标或 Skill 正文。根对象只有 `skills`，是一个有序列表；没有已有 Skill 时可省略整个文件，或写 `{"skills":[]}`。

```json
{
  "skills": [
    {
      "skill_id": "e4f5dc77-0a63-4b38-b9dc-1c51e7a1b70f",
      "version_id": "6beed1ff-749c-4ec8-9d00-a99c4618997f",
      "path": "skills/report-writer"
    },
    {
      "skill_id": "ec274f73-ca53-460e-83b2-2a67d23cb02a",
      "version_id": "a7a1ee16-66cc-4350-9af4-e6ef3df3d934"
    }
  ]
}
```

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `skills[].skill_id` | 是 | 目标空间中已有 Skill 的 ID。同一个 Skill 只绑定一次。 |
| `skills[].version_id` | 是 | 该 Skill 的已发布版本 ID，不是 `v1` 等版本标签。有本地目录时用作比较基准，否则直接引用此版本。 |
| `skills[].path` | 否 | Workspace 相对路径，必须指向 `skills/` 下的一级子目录，如 `skills/report-writer`。目录须含 `SKILL.md`，且只能关联一个 Skill。只有省略才表示仅引用已发布版本；空字符串、`null` 或无效路径在发布预览时报错。 |

第一项按本地 `SKILL.md` 和资源与基准版本比较，有变更才给原 Skill 发新版；第二项仅引用。`skills/` 下含 `SKILL.md`、且未被 `path` 引用的一级子目录按新 Skill 处理，不按名称猜测身份。要移除已有绑定，从 `proj.json` 删掉对应项，并把对应的本地 Skill 目录移出 `skills/`（如果存在），否则会被识别成新 Skill；这不会删除目录中的已发布 Skill。发布清单保留 `proj.json` 的绑定顺序，并按目录名追加新 Skill。正式的 `agent.json.skills` 由最终发布清单生成，不从工作区 `agent.json` 另读一套绑定。

### 2.4 草稿调试

从 Step 2 点击「去试试」，打开对话框并开始检查最近一轮已提交的工作区快照。未绑定模型时，在同一对话框中补选模型后自动继续。服务端复用发布的会话维护锁，校验通过后先保存新增和修改过的 Skill 草稿，再保存 Agent 草稿，自动打开调试会话。在工作区修改了原本仅引用的 Skill 时，配置其 `proj.json` 绑定的 `path`，按相同的规则保存该 Skill 草稿。未修改的 Skill 继续引用原正式版本。Agent 草稿中的 `agent.json.skills[]` 对本次保存的 Skill 使用 `version: latest`，对正式引用保留版本标签。

保存成功后复用普通会话创建入口。本空间的 `version_id: latest` 在创建时解析 Agent 草稿，仅在没有草稿时选最新可用正式版本。实际选中的 Agent 内容、草稿修订及 Skill 包引用固定在会话记录中。因此，后续覆盖保存 Skill 草稿不会改变已有会话使用的包。从「去试试」进入时隐藏左侧会话列表，并提供返回创意会话的入口。从普通会话记录打开调试会话时，沿用普通会话布局。创建调试会话不触发 Run 或发布正式版本。

同一个创意会话调试或发布时复用已保存的 Agent 和 Skill ID。发布时根据目录现状及草稿修订重新核对，所有 Skill 正式版本确认后，用正式版本标签替换 Agent 配置中的 `latest`。其他人在管理页修改草稿导致修订冲突时，停止后续写入并保留已保存的草稿。

### 2.5 发布与失败处理

确认页按「新建并发布 / 编辑并发新版 / 仅引用」展示清单。确认后，服务端先占用当前会话的 Workspace 维护锁，再校验所选快照和最终清单。对需要写入的项，从快照组装目录文档，复用现有目录服务创建或更新草稿，再用保存成功的 `revision` 调用现有发布逻辑。Skill 的正文、目录和资源一并按现有包格式保存到草稿；Agent 的 `AGENTS.md` 和 `agent.json` 分别作为正文和配置。发布时保留原快照中的文件。草稿是目标空间管理页可见的普通目录草稿；预览不写草稿，不新增创意专用草稿表、编辑接口或独立的「只存草稿」按钮。

**发布与新 Run 互斥。** 确认和重试均复用 `BeginWorkspaceMaintenance` / `EndWorkspaceMaintenance`。在同一会话写锁下，Run 提交和维护占用原子竞争：Run 先入队，发布返回 `409`，不写入目录；发布先占用，新的 Run 提交返回 `409`，不接收消息、不创建 Run。重复确认也不能并行执行。该占用覆盖全部 Skill 和 Agent 的校验、打包和提交；成功、失败或取消时，等本次操作停止写入后，沿用现有维护接口的独立清理上下文释放，不受 HTTP 请求取消影响。不新增持久化锁或 Run 状态，也不阻塞其他会话。当前页面发布中禁用再次确认和发送，其他页面的并发提交由服务端拦截，发送失败保留输入。

**工程快照只读。** 预览、确认和重试均只读取普通会话 Run 已提交的工程快照；发布流程不生成、上传、复制或覆盖任何远端工程快照，也不触发 Run 来补写快照。发布所需快照不可用时直接报错。目录草稿和正式 Agent / Skill 版本仍按现有规则保存到 TOS；它们不是工程快照。

1. **全新 Skill：** 创建含 Workspace 正文和资源的草稿，再发布首版。名称冲突时报错，不把同名 Skill 当作待更新对象。
2. **已有 Skill 有改动：** 保留 `skill_id`，核对基准版本和 `expected_revision` 后保存草稿，再发布新版本，不覆盖冲突的未发布草稿。新建和更新都不指定 `label`，复用现有自动编号：该 Skill 的最大 `vN` 加一，自定义标签不参与编号。发布清单展示实际返回的版本号。
3. **已有 Skill 无改动：** 不调用写接口，保留原版本。

有目标 Agent 时，在 Skill 写入前校验其权限和归档状态；首次发布尝试还要核对基准版本和起始草稿修订号。重试时按下文规则区分已发布和真正需要写入的项。所有 Skill 版本确认后，将准确的正式绑定写入待发布的 `agent.json`：

- **新建 Agent：** 用最终配置与绑定创建 Agent 草稿，再发布首版。创建草稿时复用当前空间的 Agent 重名校验，冲突返回 `409`，不覆盖已有 Agent。不要求在写入 Skill 前预检 Agent 名称；已发布的 Skill 按部分失败规则保留。
- **升级 Agent：** 更新会话固定的原 `target_agent_id` 的草稿，再发布新版本。更新草稿前再次核对目标 Agent 的基准版本和起始 `expected_revision`；有冲突时提示重新打开迭代，不覆盖。复用现有默认版本规则：首次发布自动设为默认；已有默认版本不被替换，可在 Agent 管理页手动切换。

整个流程不是跨对象事务，保存草稿与发布版本也是两步。某一项失败时停止后续步骤，保留已发布的 Skill 版本以及已成功保存的普通目录草稿，不回滚或另存副本。如果草稿已保存但发布失败，用户可以在现有管理页查看和编辑，或回到创意弹窗重试。宿主工作区丢失时，仍从本次发布固定的 Run 工程快照恢复，而不是用目录草稿恢复整个工程。普通管理页的编辑和发布接口不变。

#### 部分成功后的安全重试

重试沿用同一份已提交的 Run 快照及原发布计划中的目标 ID 和基准修订，从第一项重新校验，不按上次响应中的成功列表跳过。Skill 绑定从该快照重新推导，没有弹窗内的选项需要恢复。对原计划要写入的 Skill 和 Agent，按稳定的目标 ID 读取该对象最新可用的正式版本（按发布时间，不取默认版本），与快照中的待发布内容比较：Skill 比较 `SKILL.md` 和资源路径及内容；Agent 比较 `AGENTS.md` 和生成后的 `agent.json`，包括最终绑定的 Skill 版本。不比较 ZIP 字节。

首次确认在普通会话的 `session.jsonl` 写入 `creativity_publish_planned`，记录快照 ID、目标目录 ID、版本／草稿修订基准、待发布项预分配的正式版本 ID，以及为未绑定 Agent 选择的模型 ID（如有）。该记录成功保存后才写目录。草稿调试会补记实际保存的草稿修订，以便继续试运行或正式发布。记录不包含工作区文件。

确认接口保留原有错误状态码，失败且清单已生成时，在 `details.result` 返回本次逐项结果：已发布、仅引用、草稿已保存但未发布、失败、本次未处理或结果待核实。已发布和仅引用的项展示实际版本号；目录提交无法确认时不显示为成功。重新打开弹窗只读清单，再次确认时从目录现状重新核对，不用上一次的结果决定跳过哪些项。

- **内容一致：** 复用原计划的基准版本，或复用计划中预分配 ID 对应的已提交版本。目录提交成功但响应或完成记录丢失时，同一快照的重试先核对该版本，再补记发布结果。旧发布计划继续使用内容比较恢复已有结果。
- **正式版本不一致或尚未发布：** 先核对原正式版本基准。若首次尝试已保存本次内容、当前草稿仍匹配预期修订和内容，则直接用该草稿发布，不重复保存；否则只在起始修订未变或新建目标尚不存在时创建或更新草稿。若正式版已被其他发布推进且内容不同，或草稿已被改成其他内容，报冲突停止，不覆盖。提交时校验正式版本基准和本次实际发布的草稿修订，防止校验后的并发修改。
- **目标身份不变：** 已有对象沿用原 ID；新建项在首次确认前由服务端为本次发布固定目标 ID，重试沿用，不能以同名条目判断草稿或正式版本是否已写入。仅引用或相对于基准未修改的 Skill 仍使用原固定版本，不因重试升级。

#### 同一创意会话连续发布

Agent 正式发布完成后，追加 `creativity_publish_completed`，保存该快照实际发布的 Agent 和本地 Skill 版本与草稿修订。下一轮的新发布计划接续该记录。已有本地 Skill 按绑定 ID 识别，未写入 `proj.json` 的本地 Skill 按上次发布时的目录路径识别。显式选定的仅引用 Skill 继续使用原版本。历史会话缺少可以确认的发布完成记录时，从管理页基于当前正式版重新开始迭代。

预览和确认仍要求使用最新 Run 已提交的工程快照。成功记录只用于取得下一轮的发布基准。提交时继续按目录当前的正式版本和草稿修订检查并发修改。

## 3. 验收要点

- 空间默认进入「创意」，发送后进入普通会话；首条消息只发一次，不显示会话记录，返回能回到创意首页。打开、关闭发布弹窗不丢失会话。
- 发布清单只读，不展示文件树或文件预览；除了为未绑定的 Agent 补选模型，不能编辑 Agent、切换目标或变更 Skill，确认请求也不能覆盖清单。回到会话修改并提交新 Run 快照后，重新打开弹窗才显示新内容。创意新建 Agent 默认为「空间内」，仅在管理页调整权限范围。
- 快照中的 Agent 未绑定模型时，发布弹窗先要求选择当前空间的可用模型，再检查 Skills 并展示清单。已有模型时不提供替换入口；确认后重试沿用所选模型，工作区和快照不被改写。
- 普通会话左侧显示会话记录。创意会话及从「去试试」进入的调试会话隐藏左侧会话记录。各入口均保留右侧文件树，打开或关闭文件预览不影响聊天输入、消息流或目录展开状态。切换会话后不显示上一会话的文件。
- 宿主目录丢失且已有 Run 快照时，重新打开文件树即可恢复最近已提交的快照，不触发新 Run 或快照写入；仍存在的目录和其中的本地改动不被覆盖。
- 当前会话排队或运行时，「去发布」和「确认发布」均不可点击；从已打开的旧页面提交也会被服务端拒绝，不写入 Agent 或 Skill。运行结束并提交快照后可进入发布流程。
- 打开弹窗预览本身不阻止新 Run；从两个页面同时确认发布和发送消息时，先占用会话的一方继续，另一方收到 `409`，不产生相应写入。发布失败或取消后，同一会话可重新发送或重试发布。
- 从 Agent 管理页点击已有 Agent，直接进入创作会话且不自动发送消息。Agent 默认版本不是最新、Skill 绑定指向旧版时，仍从 TOS 恢复 Agent 与各绑定 Skill 的最新可用正式版本。在首次 Run 前清除宿主工作区、发布更新的 Agent 或 Skill 版本并重启服务，仍按 `session.created` 固定的版本恢复；有 Run 快照后重启则保留会话改稿。
- 已发布 Skill 的资源超过 Workspace 快照单文件阈值时，创意迭代不会以不完整的工作区继续；普通 Skill 发布和使用规则保持不变。
- 确认升级后沿用原 Agent ID，生成新版本，不改变已有默认版本或历史会话。仅有草稿的 Agent 能从同一入口发布首版；基准版本或草稿修订号冲突不覆盖。
- 对话修改一个已有 Skill、新增一个 Skill，不交付 ZIP 也能从 Workspace 预览并发布；普通 ZIP 产物仍能正常交付和下载。后续 Run 不改变已打开弹窗的发布内容。
- 确认后验证新 Skill 创建并发布首版、已有 Skill 沿用 ID 且版本自动递增、未改 Skill 不发新版，新旧 Agent 各自沿用所绑定的版本。
- 验证 `proj.json` 中带 `path` 的绑定按基准比较，不带 `path` 的绑定只引用；错误的版本归属、重复绑定或无效目录在预览时报错，不当成新 Skill 发布。
- 创作 Agent 只由配置的空间 ID 和 Agent ID 定位；填错空间 ID 或缺少任一配置时，不选用其他空间的 Agent，普通流程不变。
- 在空间 A 将已发布的创作 Agent 设为公开。只有空间 B 权限的用户可从 B 发起创意会话、刷新页面并使用绑定的模型和 Skill 资源；其文件与发布结果均留在 B，不能读取 A 的草稿或不属于该公开版本的资源。切换 A 的默认版本不改变 B 已有会话的版本；切回「空间内」后，B 不能再创建相应会话，已打开的会话不能发起新 Run，历史保留。
- 跨会话快照或跨空间 Skill 被拒绝；未归档的发布文件可定位到路径；过期草稿不会被覆盖。
- 预览、确认发布和失败后重试均不新增或改写远端工程快照；快照不可用时不补写、不发布。发布成功的正式版本包仍可从 TOS 读取。
- 部分发布失败时，保留已发布版本和已成功保存的目录草稿。若某项草稿已保存但发布失败，管理页可用原接口打开；未被修改时重试直接发布该草稿，不重复创建或保存。删除宿主目录后仍可从本次发布使用的 Run 工程快照恢复。
- 已有 Skill 从 `v3` 发到 `v4`、新 Skill 发到 `v1` 后，Agent 发布失败：重试从头校验，内容一致时复用 `v4` 和 `v1`，不重复创建或升版。即使上次成功响应丢失也应复用；若该 Skill 已发布内容不同的 `v5`，则报冲突，不发 `v6`。
